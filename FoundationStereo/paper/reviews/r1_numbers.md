검증 기준: `report/paper_results.md`(단일 진실 소스) + `experiments/_paper_numbers.json`(원본).
검증 일자: 2026-06-06. 심각도 내림차순 정렬.

## 총평

초안의 표 1·2·3, 초록, 결론의 **모든 핵심 수치는 검증값과 일치**한다. 금지된 옛 수치
(0.51/0.74/0.68/0.80 AUC, baseline 0.08 m, 1024×576, bad@1px 8.0/96.6)는 **발견되지 않았다**.
n 사용(처리 1,537 / 평면 평가 1,536)도 각주 포함 일관적이다. 그러나 아래와 같이
(a) 원자료와 긴장 관계인 주장 1건, (b) 두 출처 파일에 근거가 없는 수치 3건,
(c) 표현·반올림 경미 사항 5건이 있다.

## 중대 (Major) — 수정 필수

### M1. "시드 간 차이가 모든 지표에서 1% 미만" 주장이 원자료와 불일치 (§5 통계 규칙, ℓ77)

- 원자료(`paper_results.md` §2): 비거울 disp MAE **0.209 vs 0.222 px** (seed0/seed1, 상대차 ~6%),
  거울 disp MAE 8.723 vs 8.840 (~1.3%), depth MAE 0.151 vs 0.148 (~2%).
- "모든 지표에서 1% 미만"은 상대 기준으로 반증 가능하며, 리뷰어가 시드별 수치를 보면 바로 걸린다.
- **수정 제안**: "두 시드의 뷰별 중앙값이 사실상 동일하여(예: 거울 disp MAE 8.72/8.84 px)
  결론이 카메라 샘플링에 강건함을 확인하였다"로 완화하고, 시드별 수치를 표 1 각주 또는
  부록으로 제시. '1%'라는 정량 임계를 쓰려면 어떤 지표·어떤 정의(절대 %p vs 상대)인지 명시.

### M2. 표 2 캡션 "공통 test 뷰"가 원자료의 test 뷰 수와 불일치 (§5.3, ℓ111–123)

- `_paper_numbers.json`: view_split test **464뷰**, rep_view test **459뷰**, scene_split test **511뷰**
  — 세 체제의 test 집합 크기가 서로 다르므로 문자 그대로의 "공통(동일) test 뷰" 비교가 아니다.
  표의 수치(0.958/0.955/0.928)도 각 체제 **자체 test 집합**의 overall 값이다.
- **수정 제안**: 표 2에 체제별 test 뷰 수 열(464/459/511)을 추가하고, 캡션을
  "동일 프로토콜(136-d, MLP 136→64→1, 뷰당 4,000px, 300 epoch)로 학습한 체제별 비교"로 교체.
  실제로 교집합 test 셋에서 재평가한 것이 아니라면 "공통 test 뷰" 표현은 삭제.

### M3. single_scene(own 0.985/0.715, 교차 0.908/0.425) 행의 출처가 두 검증 파일에 없음 (표 2, ℓ117/121)

- `_paper_numbers.json`의 detect에는 view_split/scene_split/rep_view만 존재.
  `paper_results.md`는 포함 기준에서 "단일 씬 특화 모델(일반화 불가 설정) **제외**"를 명시
  — 진실 소스의 제외 원칙과 초안 표 구성이 충돌한다.
- 수치 자체는 작업 지침의 검증값과 일치하므로 사용 가능하나, 추적 가능성이 없다.
- **수정 제안**: (i) `scripts/verify_paper_numbers.py`에 single_scene 집계를 추가해
  `_paper_numbers.json`에 기록하거나, (ii) 표 2 각주에 "single_scene 두 행은 상한(own)·
  하한(교차) 참고선이며 일반화 평가 대상이 아님"을 명시해 진실 소스의 제외 원칙과 정합시킬 것.

### M4. §5.2 씬별 post-entropy 수치(0.527~0.732, computer_room 0.732, blue_bathroom 0.684)의 출처 부재 (ℓ105)

- `_paper_numbers.json`의 rq2_ahcf에는 전체 median/mean만 있고 **per-scene 항목이 없다**.
  `paper_results.md` §3에도 씬별 수치 없음.
- **수정 제안**: 검증 스크립트에 R2 per-scene 집계를 추가해 JSON에 수록한 뒤 인용하거나,
  수록 전까지는 범위 주장(0.527~0.732)을 본문에서 빼고 "모든 장면에서 우연 수준(0.5) 상회"
  정도의 정성 서술로 보수화.

## 경미 (Minor) — 권장 수정

### m1. 서론 괄호 "(AUC 중앙값 ≈ 0.59)"의 위치가 인과를 흐림 (ℓ20)

- "단일 채널의 분리력은 약하지만(AUC 중앙값 ≈ 0.59) AHCF 통과 후 일관되게 상승하여(0.545→0.587)"
  — ≈0.59는 **상승 후(post)** 값(0.587, best 0.591)인데 문장 구조상 상승 전 값으로 읽힌다
  (실제 pre는 0.542~0.545).
- **수정 제안**: "단일 채널 분리력은 AHCF 이후에도 약하지만(post AUC 중앙값 ≈ 0.59),
  통과 전후로 일관되게 상승하여(0.545→0.587)…"로 재배치.

### m2. 서론 기여 항목 "장면당 학습 뷰 1장만으로도 AUC 0.96" (ℓ26)

- rep_view 실제값 0.955. 반올림 0.96은 산술적으로 맞으나 §3.2(0.955)·표 2(0.955)·
  결론(0.955)과 유효숫자가 어긋나고 view_split(0.958→"0.96")과 동급으로 오독될 여지.
- **수정 제안**: 본문 전체에서 0.955로 통일(같은 줄의 "미지 장면 0.93"은 0.928과 함께
  병기 권장: "0.93(=0.928)").

### m3. scene_split 평가 규모(미지 4씬 511뷰) 본문 미기재 (§5.3)

- 검증값 스펙은 "미지 4씬 511뷰"인데 표 2에는 train 규모(8장면 1,026뷰)만 있다.
- **수정 제안**: M2의 test 뷰 수 열 추가로 함께 해결(scene_split 행에 "4씬 511뷰").

### m4. 두 출처 파일에 없는 보조 수치 2건 — 출처 명시 필요

- §3.3 단위테스트 조건(점 노이즈 2 cm, 무대응 40%, 법선 오차 <3°)과
  Fig 2 캡션의 단일 뷰 IoU 0.77(blue_bathroom v51): 검증 파일에 부재.
  (참고: scene_split의 blue_bathroom **씬 평균** IoU는 0.602 — 0.77은 v51 단일 뷰 값임이
  캡션에서 구분되도록 유지할 것.)
- **수정 제안**: 단위테스트는 코드 경로(테스트 파일명) 각주, Fig 2 IoU는 해당 뷰의
  metrics CSV 행을 출처로 기록(`experiments/_splits/scene_split/applied/metrics_*.csv`).

### m5. 표 1 통합 중앙값의 산출 방식 미명시 (ℓ83–92)

- 0.21 px / 2.6% 등은 시드별 중앙값(0.209/0.222, 2.59/2.78)의 중간값이 아니라
  **두 시드 풀링 후 전체 뷰 중앙값**이다. 현재 캡션 "두 시드 통합 1,537뷰"만으로는
  시드별 수치를 아는 독자가 0.21을 재현하지 못할 수 있다.
- **수정 제안**: 표 1 각주에 "두 시드 1,537뷰를 합쳐 뷰별 중앙값을 취함(시드별: 0.209/0.222 px)"
  형태로 산출 방식과 시드별 값을 병기 — M1의 완화 문구와 일관되게.
